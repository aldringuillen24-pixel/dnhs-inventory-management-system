# Coding Style Rules

- Follow the coding conventions already used in the project.
- Use descriptive and meaningful names.
- Avoid abbreviations unless they are commonly understood.
- Keep functions and methods small and focused.
- Avoid deeply nested conditions when a clearer approach is possible.
- Prefer early returns when they improve readability.
- Avoid duplicated code.
- Avoid unnecessary comments that simply restate what the code does.
- Add comments when they explain important reasoning or non-obvious behavior.
- Do not leave unused variables, imports, methods, or files.
- Keep formatting consistent with the project's existing formatter.
- Do not change formatting in unrelated code.
