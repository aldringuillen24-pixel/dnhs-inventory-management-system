# Documentation Rules

- Keep documentation consistent with the actual implementation.
- Do not document functionality that does not exist.
- Update relevant documentation when a significant feature or architectural change is made.
- Use clear and concise technical language.
- Explain configuration, setup, important workflows, and non-obvious architectural decisions.
- Avoid unnecessary documentation for self-explanatory code.
- Do not duplicate information across multiple documentation files unless necessary.
- Prefer examples when they make technical instructions easier to understand.
